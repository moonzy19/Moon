# Admin Notification Center

The HR dashboard header uses three compact actions immediately beside the signed-in profile:

1. **People** — pending new employee registrations.
2. **Messages** — new employee suggestion-box entries.
3. **Bell** — general operational alerts.

## Bell events

The durable `public.hris_notifications` stream uses `event_code`, `event_key`, `entity_id`, and `metadata`. The current event catalog is:

| Event | Trigger | Destination | Icon |
| --- | --- | --- | --- |
| `EMPLOYEE_REGISTRATION_NEW` | New inactive Karyawan registration | Employee registration | person |
| `FEEDBACK_NEW` | New employee feedback | Feedback inbox | message |
| `LEAVE_REQUEST_NEW` | Pending leave / permission request | Approval center | leave |
| `PROFILE_CHANGE_REQUEST_NEW` | Pending employee profile/data change | Approval center | person |
| `ATTENDANCE_REQUEST_NEW` | Pending attendance correction | Approval center | clock |
| `OVERTIME_REQUEST_NEW` | Pending overtime request | Approval center | clock |
| `CONTRACT_EXPIRING_SOON` | Active contract ends within 7 days | Documents & Compliance | calendar |
| `RECRUITMENT_APPLICATION_NEW` | New V25 candidate application | Recruitment ATS | recruitment |

Event creation is idempotent per recipient through `event_key`. The time-based contract reminder is generated by `hris_generate_admin_notifications()` when the authenticated admin notification center polls; the trigger-based events arrive as soon as their source rows are created.

The UI localizes system-generated titles/messages by `event_code` and `metadata`, so changing the dashboard language does not leave new notification text in the language used by the database trigger.
